## 6. Compatibility decision for the database

The live database (if `db/schema.sql` was ever executed) already contains `messages` with
`external_id`, `chat_id`, `content`, `timestamp`, `processed`, and a **global UNIQUE on `external_id`**.

`database/schema.sql` therefore **extends** those tables additively and never renames or drops a
column. `database/migrations/002_extend_legacy.sql` upgrades an existing installation in place with
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.

Running the new schema on a fresh database and on the legacy database both end in the same shape.
